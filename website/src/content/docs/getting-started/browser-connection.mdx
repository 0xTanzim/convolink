ConvoLink can work with the AI tabs you already use or with a separate browser profile for automation. The best connection depends on the browser and whether you want to reuse your everyday profile.

## Choose a connection

| Browser and use case | Transport | Port | Best for |
| :--- | :--- | :--- | :--- |
| Chrome, Brave, Edge, or Chromium everyday profile | Companion Extension | `9224` | Using your existing signed-in tabs without debug flags or a restart. |
| Firefox or Zen | WebDriver BiDi | `9223` | Native browser automation; installing the extension is optional. |
| Separate Chromium profile, headless, or CI | Chrome DevTools Protocol (CDP) | `9222` | A dedicated profile you can configure for automation. |

## Chromium: use the Companion Extension for your everyday profile

Chrome 136 and newer require a non-default user-data directory to enable remote debugging. A browser launched with debugging flags can therefore be a different profile from the one where you are signed in. The Companion Extension connects to your existing Chrome-family browser without those flags.

1. Install the [Companion Extension](/convolink/extension/overview/).
2. Run `convo ext pair` and follow its instructions to pair the extension with the CLI.
3. Run `convo doctor` to confirm the bridge and tabs are available.

The local extension bridge listens on `127.0.0.1:9224`. Pairing authorizes the local CLI to use the extension; it does not enable arbitrary JavaScript execution.

<Aside type="caution" title="Do not add debugging flags to your everyday profile">
  For Chrome 136+, use the extension with your normal profile. If you need CDP, launch a separate profile with its own `--user-data-dir` and sign in to the AI sites there.
</Aside>

## Firefox and Zen

Firefox and Zen have native BiDi support. Use the matching command to launch/connect through ConvoLink:

```bash
convo connect --firefox
# or
convo connect --zen
```

ConvoLink enables BiDi for the selected browser profile and connects over the local endpoint on port `9223`. The Companion Extension is available as an optional alternative, but it is not required for Firefox or Zen.

If the selected browser is already open without BiDi enabled, close it normally and retry the command. The command reports this condition rather than silently replacing that browser session.

## Chromium CDP: use a dedicated profile

CDP is useful for repeatable automation, headless runs, and CI. Start Chromium with a non-default profile directory and port `9222`:

<Tabs>
  <TabItem label="Linux">
    ```bash
    google-chrome \
      --remote-debugging-port=9222 \
      --user-data-dir="$HOME/.convo/chrome-profile"
    ```
    Replace `google-chrome` with your Chromium, Brave, or Edge executable as needed.
  </TabItem>
  <TabItem label="macOS">
    ```bash
    "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
      --remote-debugging-port=9222 \
      --user-data-dir="$HOME/.convo/chrome-profile"
    ```
  </TabItem>
  <TabItem label="Windows PowerShell">
    ```powershell
    Start-Process "chrome.exe" -ArgumentList @(
      "--remote-debugging-port=9222",
      "--user-data-dir=$env:LOCALAPPDATA\ConvoLink\ChromeProfile"
    )
    ```
  </TabItem>
</Tabs>

Sign in to the AI sites in this profile, then run `convo doctor`. Keep the profile directory dedicated to this automation session.

## Confirm the active connection

```bash
convo doctor
convo status
```

`convo doctor` checks browser connectivity and supported AI tabs. `convo status` shows the resolved browser, transport, endpoint, and configuration source. To inspect extension pairing and build details, run:

```bash
convo ext status
```

## Choose a browser profile

When multiple browser profiles are available, list and select one:

```bash
convo profile list
convo profile select work@example.com
```

The selected profile is saved for the current workspace. Use `convo status` to confirm the resolved configuration.

## Security and ownership

- Browser transports connect to a local browser; they do not send prompts through a ConvoLink-hosted service.
- The extension accepts a fixed set of operations. It does not expose arbitrary page JavaScript evaluation.
- ConvoLink avoids stealing window focus and does not close browser tabs it did not open.
- Keep a CDP debugging port bound to a trusted local environment and use a dedicated profile.

For extension permissions and pairing, see [Companion Extension](/convolink/extension/overview/) and [pairing](/convolink/extension/pairing/).
